## 1. 产品决定

网站围绕**一条**个人学习主线组织，不再用三条平行求职路线加六个作业项目作为入口。同一主线按能力推进，分成三个阶段：

1. 小模型学习实验室
2. 技术声明核验助手 / 单 Agent
3. 算法或 Infra 专项实验

去掉现有六个平行项目作为作业：`log-analyzer`、`hf-mini-lab`、`llm-eval`、`rag-service`、`sft-lora`、`inference-benchmark`。它们不再出现在主导航、主线任务和项目完成进度里。最终可以删除不再需要的代码，但必须先审计引用和可复用部分；不要直接删整个 `projects/`，也不要把目录整体搬到 `legacy/` 就算完成。新主线不为了保留旧代码而依赖这六个项目。

原有理论教材、交互演示和有用的参考内容继续保留。涉及旧项目的 Guided Build 必须逐项改写、迁移或移除，不能留下指向已删除目录的操作指南。

前八周以一年计划为准，从 Attention 和小模型实现开始。Python / PyTorch 基础并行补充。基础 SFT 和评测仍在前八周，不推迟到专项阶段。

调研中的 92 个项目是参考资料，不是待完成任务。不为这些工具分别创建新的主项目卡片。优先使用：SpongebobLite、CS336 部分作业；Hello-Agents；CHEF；mini-swe-agent（最小循环完成后再读）；Pydantic AI、Inspect AI 按项目需要；TRL 或 vLLM 作为后期专项工具。

## 2. 「我的学习」

需要一个明确入口（名称可以是「我的学习」或等价主入口），显示：

- 当前阶段（**同一主线的三个阶段之一**）
- 本周目标（周数是预算，不是按日历强制解锁）
- **一个**主要任务，以及完成它所需的补基础内容（并行、不挡主任务）

每项任务必须关联：

- 知识点（可多个；见第 3 节）
- 已有教材（章节、参考手册、外部阅读）
- 实现任务（空文件 / 小仓库里本人要写的内容）
- 验收标准（能检查、能解释，而不是“看完就算”）

阶段按能力推进：未通过当前验收时缩小任务或继续当前任务，不随日历自动跳周。允许手动把当前阶段改到主线上的另一阶段。未通过验收**不硬锁**教材、答案和后续内容。日期、出国、考试可以推迟周预算，不改能力门槛。

### 3.2 知识点与任务

- **任务**是主线上一次要完成的工作（例如「手写因果多头注意力」）。
- **知识点**是可复用概念，有稳定 id，例如 `attention`、`causal-mask`、`tensor-shape`。
- 一个任务关联**多个**知识点。同一知识点可被后续任务再次使用。
- **知识点记录可以复用**：四个独立维度挂在 conceptId 上，后续任务看到的是同一套概念记录。四个维度是：读过、自己实现、验证通过、能解释；互不自动推导。不要求每个概念都填满四项。例如 `tensor-shape` 可以通过解释和操作验证，不必另造「实现张量形状」作业。
- **任务完成只依据该任务的全部必需验收项。** 概念记录用于薄弱点、历史和后续复习，不再作为第二套推进门槛。
- **任务验收记录不可因概念历史自动完成。** 每条验收证据绑定 `taskId + criterionId`，可以额外关联 `conceptId`。某个知识点过去已有「自己实现」或其它证据，不得把引用它的新任务或其 criterion 标成已通过。
- 计划定义（发布数据）列出任务、知识点 id、criterion id，以及每条验收是必需还是拓展。个人存储只写这些 id 上的状态与证据。
- **第一功能阶段只把这条边界写进约定和计划 JSON。** 阶段 3 第二步已实现最小记录层：验收结果、概念四维、短记录与卡点存在本机；任务完成只看全部必需项的当前用户自报通过。

### 3.3 验收与证据

每个任务写清**通过条件**（可观察、可复述）。任务完成只看该任务定义里的**全部必需验收项**，由数据读取，不硬编码「三条」或「四条」。拓展项未完成不阻挡核心任务。

**证据来源与检查结果分开。**「有证据」不等于「通过」，「做过检查」不等于「验证通过」。

每项验收至少区分结果：

| 结果 | 含义 |
|---|---|
| 未检查 | 还没有按该条做过检查 |
| 未通过 | 做过检查，当前明确未达到条件 |
| 用户自报通过 | 用户明确确认达到条件，并记下对应依据 |

每条记录还要带 **来源**：

| source | 含义 |
|---|---|
| `user_reported` | 用户自己填写或勾选 |
| `auto` | 本站或本地脚本实际跑过并写入 |

`user_reported` 表示来源，**不表示成功**。没有自动脚本时只生成 `user_reported`，不能显示成自动验证通过。界面必须能看出自报与自动的区别。

失败后修好可追加新结果，**保留**原错误记录。完成状态依据**当前**明确的验收结果，不能因历史上曾通过而忽略后来明确的失败。无需引入复杂事件系统。

同一份代码或测试输出可以关联多个验收项，但每项仍须明确对应与结果，不能自动泛化为全部通过。

默认一次学习只需简短记录：做了什么；检查结果及代码位置；下一步。解释可写一句要点，不要求长报告。允许一句可选备注「查 API／提示后完成／看过参考后重写」；不新增评分，不把求助当处罚。

卡点尽量具体，例如「拆头后不知道为何需要 transpose」，而不是「不会 PyTorch」。

满足全部必需验收项后，提示「进入下一任务」，由用户确认切换。不随日历或最后一次勾选自动推进。手动浏览或选择后续任务，不代表补齐此前的完成状态。未满足时首页仍停在当前主要任务。教材与后续章始终可打开。

### 3.4 当前任务与推进

- 首页只突出**一个**主要任务 + 必要补基础（例如卡在 `reshape` 时显示第 11 章对应小节）。首页突出下一动作，详情按需展开。
- 任务未完成就继续该任务；**不按日历把第 1 周自动换成第 2 周**。
- 用户可手动选择当前阶段（仍是同一条主线上的实验室 / 核验助手 / 专项）。
- 未通过验收不隐藏教材、参考答案或后面章节。

### 3.5 主动复习

复习形式：解释、闭卷回忆、或复写核心函数。默认间隔 1 / 3 / 7 / 21 天，可改。复习按 concept 排队，不复制 task。只展示已到期项。结果只有通过 / 未通过。失败记下薄弱知识点，建议重练**当前或更小的任务**；**不删除、不改写**此前真实的实现和验证记录，也不把历史 `user_reported` 改成失败。复习不得按日历推进或倒退首页主任务，也不得因到期打开新的主线任务。任务证据与复习状态是两套数据。3b-1 数据模型已封板。3b-2、3b-3、3b-4 已通过。失败后给出当前或更小任务的重练入口，匹配 `conceptIds` 和验收关联的 `conceptId`；未到期时界面不得显示成保存成功。阶段 3b 已完成。

### 3.6 机制落地节奏（禁止一次做完）

1. **展示：** 当前任务、教材、验收条件、关联知识点名称。
2. **记录：** 四个独立维度、验收结果（含失败）、卡点。任务完成只看必需验收项。
3. **复习：** 到期队列与失败后的重练。

对应工程阶段见 [`IMPLEMENTATION_PLAN.md`](IMPLEMENTATION_PLAN.md)。不因本节把证据表单和复习队列塞进第一阶段。阶段 3 开工时先统一本节规则，再按该文件列出的小步实现，不另开功能范围。

### 3.7 求助规范

允许有层次地学习，再验证独立能力。「独立实现」是**最终能脱离答案完成**，不是学习期间从未接受帮助。查 API 正常。网站不代写核心算法。

把「自检通过后才能看参考」当作**学习顺序建议**，避免一直检查失败就无法求助。建议流程：

1. 自己写输入输出、shape，并留下一次实现尝试。
2. 求助时优先请求解释报错、定位可疑步骤或给反例。
3. 仍卡住时可以看局部示例或参考实现。
4. 看过后关闭参考，重新实现关键部分，并换输入验证。

每个任务安排一个适当的小变式，检查能否迁移即可，不建设题库或评分引擎。下一次学习开始可用几分钟解释或复写一个关键步骤；这是练习说明。到期复习队列已在阶段 3b 落地。阶段 3b 已完成。

## 4. 完整示例：小模型学习实验室 — Attention

对应一年计划第 1 周。任务 id：`lab.attention.causal-mha`。发布数据在 [`../content/learning-plan.json`](../content/learning-plan.json)。

**知识点（计划数据，多对多）**

| id | 名称 |
|---|---|
| `attention` | 缩放点积注意力 |
| `causal-mask` | 因果掩码 |
| `tensor-shape` | Q/K/V 与多头拆分的 shape |
| `python-index` | 函数、索引、调试（补基础，不挡主任务） |

**页面必须可执行（第一阶段就要写清，不代写核心算法）**

- 阶段：小模型学习实验室（同一主线的阶段 1）
- 主要任务：不看参考代码重写 attention；说清每一步 shape；改变未来 token 不改变之前位置输出。第 1 周硬门槛**不包括**拼最小 decoder block（放到第 2 周）。
- **写在哪里：** 本机空文件（例如 `~/llm-lab/attn.py`），不要写进 `projects/` 六个旧目录
- **输入：** 单头为 Q/K/V，形状 `[B, T, D]`；多头再按 H 拆成 `[B, H, T, Dh]`，`Dh = D / H`；位置 t 只能看 0…t
- **输出：** 与 Q 同形状的上下文向量 `[B, T, D]`
- **步骤：** 先读 7.4 / 7.5 / 7.9 / 7.10 / 7.17 → 写单头并留下一次尝试 → 自检；卡住则按第 3.7 节分层求助 → 关闭参考后重写关键部分并换输入验证 → 读 7.14 扩多头 → 再自检。7.12 是无掩码手算理解材料；7.13 只在写完尝试后对照，不要先抄完整实现。
- **检查：** 打印每步 shape；改未来 token，过去位置输出不变；关闭 dropout，用固定输入分别核对单头和多头数值。对照须同掩码、缩放、dtype；多头还要同拆头顺序与输出投影。先确认预期输出没有 NaN/Inf，再对有限数值逐元素满足 `abs(actual - expected) <= atol + rtol * abs(expected)`。不要把 7.12 的三位小数无掩码表当成因果数值标准。本站不运行 Python，不提供核心算法答案。
- **小变式（迁移检查，不是额外门槛）：** 任选一项即可：换 batch 或序列长度并先预测 shape 再运行；换合法头数，检查拆头与拼头；故意改错 softmax 维度或 mask 方向，说清哪个检查会失败。
- **教材链接：** 必须指向第 7、11 章中实际存在的小节标题（由计划 JSON 的 `section` 字段与 Markdown `##` 对齐）
- 补基础：class / reshape / broadcasting 链到第 11 章对应小节
- SpongebobLite 仅作对照入口，标「对照用，不是本周作业仓库」

**验收条件绑定（阶段 1 只展示条文，不收集证据）**

| criterionId | 关联 conceptId | 条文 |
|---|---|---|
| `rewrite` | `attention` | 空文件中重写核心计算（先单头后多头） |
| `shapes` | `tensor-shape` | 能讲清每一步 shape |
| `causal` | `causal-mask` | 未来不影响过去 |
| `numeric` | `attention` | 关闭 dropout；固定输入；与掩码、缩放、dtype 一致的可信参考比较；多头统一拆头顺序和输出投影；先确认没有 NaN/Inf，再按组合容差 `abs(actual - expected) <= atol + rtol * abs(expected)` 比较有限数值；7.12 不是因果数值标准 |

这四条都是 `lab.attention.causal-mha` 的**必需**验收。完成与否读取任务定义里的全部必需项，不因为一共有四条就写死「必须四条」，也不因为 `causal-mask` 曾经有过阅读记录就自动完成。**首页只显示中文条文，不显示这些 id。**

**用户可记录（第二机制层；最小表单已实现）**

- 每条必需验收：未检查 / 未通过 / 用户自报通过，来源默认为 `user_reported`
- 每条验收用「保存本条记录」把当前结果和依据一起写入；未保存的修改有提示，不因换周等重绘而悄悄消失
- 用户自报通过必须写下该条的简短依据（检查结果、代码位置或一句解释）；无依据不算完成，也不改写已有有效记录
- 新提交若结果或依据有变化，旧快照进历史；完全相同则不重复追加；当前结果决定是否完成
- 证据键：`taskId + criterionId`，可选 `conceptId`
- 知识点 `causal-mask` 的四个独立维度可被第 2 周 decoder 任务看到；第 2 周任务仍要自己的必需验收，不得因概念历史自动完成
- 不要求给 `tensor-shape` 另造「实现」作业才能推进

**建议进入下一任务（例如 embedding + 最小 decoder）当且仅当**

- 本任务全部必需验收项的**当前**结果为用户自报通过，且每条都有非空的简短依据。

满足后提示用户确认切换，不自动跳走。概念层不必再勾一套「自己实现／能解释」才能推进。未满足时仍显示本任务为当前主要任务。用户仍可打开第 9 章或第 2 周教材。日历到了第 2 周也不自动切换当前任务。

## 5. 学习状态

四个独立维度分开记录，互不自动推导。它们挂在**知识点**上，用于薄弱点、历史和日后复习，**不是**第二套任务推进门槛。任务完成是「该任务全部必需验收项的当前结果是否为通过」的汇总，不是第四套平行掌握度，也不是把概念状态复制成任务完成。不要求每个概念都填满四项。

| 维度 | 含义 | 不是 |
|---|---|---|
| 读过 | 打开过或标记过对应教材 | 不是已掌握 |
| 自己实现 | 本人写过核心代码或数据步骤 | 不是测试已绿、不是能讲解 |
| 验证通过 | 按任务声明做过检查，且**当前**结果为通过（shape、因果 mask、手算 scorer、小样本过拟合等） | 做过检查但未通过不是验证通过；不能把手动勾选写成「自动测试通过」 |
| 能解释 | 能口述输入输出、失败原因或对照差异 | 不能由「已读」或 starter 全绿自动勾上 |
